# Nibiru 安全核查与修复报告

审查日期：2026-10-20（Asia/Shanghai）。范围：当前本地应用源码、HTTP API、浏览器状态、SQLite/图片/备份存储、任务归档、运行配置与依赖。审查使用隔离测试数据库，不对现有用户执行删除测试。

## 结论

本轮发现并修复了应用层的实际缺陷，同时增加了安全回归测试。**不能据此承诺“没有任何安全隐患”，当前也不建议直接公网发布。** 仍有两项上线前必须处理的事项：更换已有测试账户密码；安装 Node.js 官方尚待发布的安全修复版本。HTTPS、反向代理和主机安全也需要在真实部署环境中验证。

## 已修复的问题

| 级别/条件 | 原问题 | 修复与验证 |
|---|---|---|
| 高，本机多系统用户环境 | SQLite/WAL/SHM 原为0644，其他系统用户可能读取密码哈希、会话与邀请码 | 数据目录与备份收紧到0700，文件0600；启动时同时修复已有文件权限；测试检查实时WAL/SHM及旧文件重新打开 |
| 高，首次初始化经错误反代暴露 | 只靠loopback与转发头判断初始化请求，代理重写后可能失效 | 首次初始化另外要求独立随机密钥，保存在私有 `.setup-token`，不通过API返回；成功后删除；缺失密钥测试403 |
| 中，恶意站点/错误Host | 缺少全局Host允许列表及完整防嵌入策略 | Host只允许loopback与配置域名；精确Origin、Sec-Fetch-Site检查；CSP frame-ancestors none、DENY、nosniff、base-uri none 等安全头 |
| 中，认证资源消耗与爆破 | 同步scrypt阻塞事件循环，密码没有服务端上限，成功登录会清空失败计数 | HTTP改为有界异步scrypt；密码最多128字符；全局/IP/账户限流；成功不重置额度；每账户最多10个登录会话 |
| 中，停用后的慢请求 | 用户可以先建立慢上传，再在账号停用后完成已授权的写请求 | JSON读取完成后重新检查会话，管理操作在外部等待后再次检查权限；慢分块请求回归测试401且不创建任务 |
| 中，账户切换隐私 | 过期或退出时可能残留图片弹窗、草稿或在途响应 | 清除图片弹窗、任务草稿、预设编辑态和导出缓存；中止旧请求；使用会话代数拒绝跨会话迟到响应 |
| 中，归档资源与文件边界 | ZIP没有并发限制、路径边界不完整，读取/删除存在竞争 | 每用户1个、全局2个ZIP；导出锁阻止同用户删除；异步64KiB分块读取；拒绝符号链接和目录外路径；读取前后验证文件身份；异常不会导致未处理Promise崩溃 |
| 中，磁盘消耗 | 只有待生成数量限制，没有已保存图片的账户额度 | 默认每账户20GiB，写图保留至少1GiB可用空间；超限拒绝新任务/图片写入。额度可通过MAX_USER_IMAGE_BYTES配置 |
| 低，异常输入/错误暴露 | 畸形Cookie、null JSON、非法类型可能导致500并打印内部异常 | 容错Cookie解析；JSON必须为对象并限制1MB；返回受控错误；静态服务禁止点文件、数据库文件、目录和符号链接 |
| 运维风险 | smoke脚本包含固定测试凭据 | 改为环境变量提供凭据，目标仅限loopback；实际生成必须显式声明disposable；不自动在未知环境创建固定密码管理员 |

新注册或修改密码使用带盐 scrypt N=32768/r=8/p=3，并支持现有旧哈希登录。新增「设置 → 账户安全」修改密码入口，要求12–128位，成功后撤销其他登录会话。既有用户的密码未被擅自修改。

## 未发现直接问题的检查项

- 管理员接口均需服务器端角色校验；普通用户无法管理模型、邀请码或其他用户。
- 图片、任务、ZIP、预设与删除操作都按账户归属校验；批量删除先验证整组，包含他人ID时不部分执行。
- SQL参数均通过绑定传入；动态排序值使用固定允许值。未发现用户数据拼接为SQL执行的路径。
- 浏览器展示使用DOM/textContent，未发现把Prompt、模型名或任务名拼接到可执行HTML的路径。
- ComfyUI地址来自服务端配置；普通用户不能指定代理目标；prompt_id编码，view参数通过URLSearchParams构造。
- 会话令牌来自密码学随机数，Cookie带HttpOnly和SameSite=Strict，API与私有图片使用private,no-store。
- 敏感删除要求确认参数，活动任务不能被历史清除直接破坏。

这些结论仅适用于检查过的版本和路径，不等于证明不存在其他漏洞。

## 尚未消除的风险与发布条件

### 1. Node.js 安全补丁尚待发布

当前安装Node.js v26.10.0。官方2026年10月安全公告说明26.x、24.x、22.x发布线受到最高HIGH级问题影响，计划在2026-10-21或之后发布修复。截至本次检查，不能把非安全发布v26.12.0视为该公告的修复版。

- [官方安全公告](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)
- [官方版本索引](https://nodejs.org/dist/index.json)

公告未提供足以在本次审查中完整判定本应用利用条件的细节；没有对已运行进程进行漏洞利用验证。**上线前必须确认并安装官方安全修复版本。** 本轮没有擅自替换机器的全局Node安装。

### 2. 现有测试密码需要更换

当前预览账户曾使用并在对话中提供过测试密码，不能继续作为公开服务的管理员密码。请使用「设置 → 账户安全」自行设置随机新密码。报告不重复记录密码，代码不自动更改已有用户凭据。

### 3. 真实部署与外部系统仍需验证

- 当前为本机HTTP预览，并未部署公网TLS。对外开放须使用可信HTTPS反向代理、精确APP_ORIGIN和Secure Cookie；启动器拒绝无HTTPS配置的公网绑定，但它本身不提供TLS。
- 代理后的边缘限流、可信客户端地址、证书与安全补丁、系统访问权限、备份保管，需要在部署环境中核验。
- ComfyUI及其自定义节点、模型文件、SSH服务器和系统软件不在本仓库代码审计范围内；不要将8188直接暴露公网。
- 导出锁和限流在单进程内协调，服务按单实例部署；多实例需共享限流、导出锁和工作调度协调。
- 同一系统用户权限的恶意本地进程不属于应用账户隔离可防护的范围。
